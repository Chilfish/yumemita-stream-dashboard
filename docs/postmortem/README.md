# 事故复盘索引（Postmortems）

> **Blameless 原则**：归因于「什么系统条件允许它发生」，而不是「谁写错了」。
> **写代码前先读「基线雷区」自查**，避免复现已有的坑。

## 严重级别

| 级别 | 判据 |
| --- | --- |
| SEV-0 | 不可逆数据丢失；或生产 / 构建完全不可用且当天无绕行 |
| SEV-1 | 用户可见核心功能失效或数据损坏；错误结论被当作事实采用 |
| SEV-2 | 用户可见功能降级但可绕行；阻塞部分开发流程；中等返工 |
| SEV-3 | 局部或体验层问题，影响可控，但暴露系统性缺口 |

## 状态

- **Active**：根因未消除，同类问题仍可能复发。
- **Mitigated**：具体缺口已消除，且预防已落地或有门禁兜住。

## 基线雷区（写码前自查）

> 这些是本项目自带的通用风险，不来自某次事故。

### 1. 路由与渲染（当前 React Router + Vite）

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 真实路径可刷新 | 新增页面是否在 `src/pages/` 有对应 `.astro`，Worker 是否正确返回 404 / 200 | 直接访问、刷新深链验证 |
| URL 状态可分享 | 表格筛选 / 单场分段 / 对比 ids 是否写进 URL | 用 `parseTableParams` / `writeTableParams` |
| 旧链接兼容 | `#/...` 与旧 `overview` / `table` 是否有重定向 | Astro `redirect` + 客户端 hash 兼容脚本（阶段 3） |
| 错误边界 | 页面是否有三态与 500 兜底 | 错误态视图 / `500.astro` |
| 子路径部署 | Astro `base` 与链接前缀是否一致 | 子路径下验证链接与静态资源 |

### 2. 数据与对象存储

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 单一真源 | `streams` / `dataset_insights` 是否被手改 | 只由 `db:ingest` 从 pack 派生 |
| 提交顺序 | 是否先 ingest 再 purge | 数据库提交成功后才失效缓存 |
| 错误可见 | 数据库不可用时是否显示错误态 | 三态覆盖，不要静默空数组 |
| 增量进度 | `.publish-state.json` 是否与实际桶一致 | 怀疑漂移时 `publish:assets --force` |
| 数据缩水 | 本地 pack 少于数据库时 ingest 是否覆盖 | 确认下架流程，不要先 truncate 再灌 |
| 会员限定 | 公开范围是否确认 | 不确定就不上传公开桶 |

### 3. 样式与 UI

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 不硬编码颜色 | 是否出现 `#fff`、`rgb()`、`bg-[#...]` | 用 Token：`bg-background`、`text-muted-foreground` |
| 不用 `dark:` 补颜色 | 是否用 `dark:` 覆盖背景 / 文字 | 变量已在 `.dark` 切换 |
| 空值不画 0 | 图表是否把 `null` 当 0 | 跳过或显示「—」 |
| 移动端单独验 | 是否只按宽度断点验收 | 检查触屏、安全区、滚动锁 |
| 无障碍 | 图标按钮是否有名称、焦点是否可见 | `aria-label` + `focus-visible:ring-2` |

### 4. 构建与部署

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 部署配置来源 | 是否用根 `wrangler.jsonc` 直接 `wrangler deploy` | 必须用 adapter 生成的 `dist/server/wrangler.json`；根配置的 `assets: ./dist` 会把 `server/` 与 `.dev.vars` 当静态资源 |
| 构建期变量 | `PUBLIC_R2_BASE` / `SITE_URL` 改了是否重新构建 | 构建时注入；部署工作流显式设置 |
| R2 凭据 | 发布机是否有 `R2_*` | 只在抓取 / 发布环境注入 |
| 缓存头 | 封面 / emoji 是否长缓存，数据页是否短缓存 | 由 R2 Cache Rule 与 `Astro.cache.set` 控制 |
| 子路径 | Astro `base` 是否同时影响路由与静态资源 | 子路径下完整冒烟 |

### 5. 验证与流程

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 不把构建当功能验证 | 是否只跑了 `bun run build` 就宣称可用 | 手工走查相关页面，写清路径与预期 |
| 假绿 | 测试是否无断言、空跑或全 `skip` | 故意改坏行为确认变红 |
| 源码扫描冒充断言 | 验收标准是否只检查字面量 | 关键路径用行为测试，扫描只作辅助 |
| 计划当现状 | 文档是否把未做写成已完成 | 未完成放 backlog / 阶段方案 |
| 文档漂移 | 路径、命令、路由是否还能对上代码 | 改代码同步改文档；全局搜旧写法 |
| 死链 | 索引是否指向不存在的文件 | 合并前逐条打开检查 |
| 迁移双份事实 | Astro 方案是否被写成已上线 | 当前实现与目标形态分开写 |

### 6. Astro + PostgreSQL + Workers

| 规则 | 自查点 | 对策 |
| --- | --- | --- |
| 每页声明 `prerender` | 数据页是否误写 `true` | 数据页 `false`，稳定页 `true` |
| 岛屿 props 可序列化 | 是否传函数、类实例、`Date` | 查询层统一返回字符串 / 普通对象 |
| `client:only` 不放正文 | 首屏内容是否由 `client:only` 渲染 | 正文用 `.astro` 输出 |
| 数据库事务 | ingest 是否用了 `neon-http` 做事务 | ingest 用 `neon-serverless` WebSocket Pool |
| 缓存失效范围 | 是否以为 zone purge 会清 Workers Cache | 走 Worker 内部 purge 端点 |
| `.md` 重复收录 | `.md` 是否进了 sitemap | `X-Robots-Tag: noindex`，不进 sitemap |
| 全量弹幕体积 | 是否把 691 万条弹幕塞进热表 | 先聚合，`chat_events` 分区后再上 |
| 数据工作流依赖 | 加了 Drizzle / Neon import 后是否仍没装包 | 工作流显式 `bun install --frozen-lockfile` |
| 公开桶范围 | 逐字稿正文是否走了公开 R2 域名 | 正文走同源 `/api/transcripts/...` + binding |

## 高频雷区（来自实际 postmortem）

> 尚无。首次踩坑后按 [TEMPLATE.md](./TEMPLATE.md) 新增，并把教训浓缩到上一节对应类别。

### 经常出现的根因

1. **缺少 spike / 验证**：假设未经独立环境验证。
2. **配置来源不唯一**：同一信息分散在多处，改一处漏一处。
3. **回退静默**：失败被默认值掩盖，页面看起来正常。
4. **验证不携带信号**：构建通过被当成功能通过。

### 做对了的事

1. **先复现再修**：用可复现命令定位根因。
2. **修条件而非个案**：把预防写回规范或门禁。
