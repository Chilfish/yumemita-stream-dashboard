# 信息密度与界面冗余

> 适用范围：所有页面、视图组件与岛屿。
> 相关：[ui-design/README.md](./README.md) 的核心原则、[writing-style.md](../writing-style.md) 的界面文案、[postmortem/README.md](../postmortem/README.md) 的基线雷区。

## 1. 判断标准

一屏只回答一个问题。写页面前先写一句「访问者来这里要做什么」，再决定哪些字段进入界面。不服务这句话的数据留在 `.md` 路由、API 或详情页，不占首屏。

三条可检查的约束：

1. **一个概念只出现一次**：同一数字、同一名称、同一状态不在标题、正文、脚注里重复。
2. **一个区块一个焦点**：一个主数字或一句主标题，至多一个动作。
3. **界面不写统计口径**：口径属于 [data-model.md](../data/data-model.md)，页面只展示结果。

## 2. 四个冗余信号

| 信号 | 表现 | 处理 |
| --- | --- | --- |
| 同一事实的重复表述 | 一行 caption 与下方读数展示同样的数字；成员色点紧挨已经带颜色的头像 | 保留信息层级最高的那一处，其余删除 |
| 口径脚注 | 在区块底部解释「含会员限定」「按时长加权」「每列一周」 | 口径写进数据文档，界面删除 |
| 自证式导航 | 「单场详情 →」「进入 X 的首页 →」；区块 meta 复述统计范围 | 标题本身可点；一个区块最多一个动作 |
| 因字段存在而存在的区块 | 新面板与已有面板回答同一个问题 | 先问这个区块回答什么；与已有区块重复的删掉 |

一个直接可用的判断：**需要脚注才能说清的数字，先从这一屏删掉。** 脚注通常说明这个数在这一屏没有立足点。

## 3. 反例：2026-11-07 组首页

| 删除项 | 类型 | 原因 |
| --- | --- | --- |
| `GroupPulse` | 重复区块 | 与成员面板的累计指标重复 |
| `GroupRecentUpdates` | 重复区块 | 与 Hero / 成员面板的最近场次重复 |
| `GroupMemberEntries` | 重复区块 | 与 Hero 的成员入口重复 |
| Focus card 的播放 / SC / 同接一行 | 重复表述 | 下方 `Readout` 已展示同样的三个数 |
| 三处 `MemberDot` | 重复表述 | 头像与色条已经表达成员身份 |
| 「全组最新一场」「按最近更新排序」「全期累计 · 按公开场次统计」 | 元信息 | 不改变读者判断 |
| 「单场详情 →」「进入 X 的首页 →」 | 自证式导航 | 场次标题与成员名本身就是链接 |
| `PanelNote` 三段 | 口径脚注 | 属于 `docs/data/data-model.md`；该 primitive 已删除 |
| 页头的最近更新时间描述 | 重复表述 | 页面已有今日计划与最近场次 |

清理后首页的顺序是：今日计划 → 全组焦点 → 成员面板。没有新增区块，核心信息仍在。

## 4. 生成后的删除清单

- [ ] 每个数字只出现一次
- [ ] 每个名称只出现一次；头像或色条已经表达身份时，不再加色点
- [ ] 没有解释统计口径的脚注；`PanelNote` 与「按日本时间」「按开播时间倒序」这类区块 meta 同类，一律不再添加
- [ ] 没有「详情 →」「进入 X →」这类重复入口
- [ ] 没有与现有区块回答同一问题的新区块
- [ ] 去掉所有 caption 后，页面仍然成立
- [ ] 眯眼能看到一个主视觉；三秒能说出这屏是干什么的
- [ ] 新增的每个区块都能说出它替代了什么，而不是只增加了什么

最后一条对应审查时的净增行数：只加不减的 PR 需要说明这些新增信息为什么必须同时在场。

## 5. 人类页面与机器视图

站点已有 `/{datasetId}/stream/{videoId}.md` 与 `/api/*`。机器需要的完整字段放在这些出口，不复制到人类页面。人类页面只保留当前问题需要的信息；需要全量数据时，提供明确入口，不在首屏铺开。

## 6. 模型为什么会这样写

机制分析与外部资料见 [AI 生成界面的信息密度问题](../research/ai-generated-ui-density.md)。与本仓库最相关的四条：

- **不确定性下默认信息最大化**：不知道读者是谁、要做什么时，展示所有字段比漏掉一个更安全。
- **把解释当成默认语态**：训练语料里，文字多用于说明代码与写文档，模型容易把这套语态带进产品文案。
- **没有页面级的注意力预算**：单个组件看都合理，但视觉层级与一次展示多少内容需要页面级判断。
- **从数据模型长页面**：字段存在就找一个位置放，而不是先从读者的问题出发。这是本项目最容易复发的路径。

## 7. 验收

- 手工：浅色与深色各看一次；390 / 320px 各看一次；做三秒测试与眯眼测试。
- 文档：新增页面在 `docs/` 里写明这一屏回答的问题。
- 审查：PR 模板的 UI 项勾选「信息密度」；审查按 [reviews/README.md](../reviews/README.md) 的清单检查。
