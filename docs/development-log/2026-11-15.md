# 2026-11-15

## 用 claude-seo 审计线上站点

试跑 [claude-seo](https://github.com/AgriciDaniel/claude-seo)（MIT，Claude Code 的 SEO 插件）对 `https://ymmt.chilfish.top` 做外部审计，结论落成 [research/seo-audit-2026-11-15.md](../research/seo-audit-2026-11-15.md)，待办登记 backlog B38。

### 做法

不装插件（本机以 Claude Code 之外的 agent 为主），只复用它的脚本层：`git clone --depth 1` + `uv venv` + 装 `requests / beautifulsoup4 / lxml / trafilatura`，然后直接跑 `sitemap_discovery.py`、`transport_check.py`、`agentic_check.py`、`page_checks.py`。判断层（评分权重、优先级、报告结构）按 `skills/seo/SKILL.md` 的 playbook 执行。另写一轮抽样巡爬：`sitemap.xml` 分桶、每桶随机 8 条、共 42 条。

### 结果

健康分约 82/100。结构层面很干净：0 非 200、0 重复标题/描述、canonical 与 JSON-LD 全覆盖、404 是真 404、`.md` 视图带 `X-Robots-Tag: noindex` + `Content-Signal` + `rel="alternate"`。

两个真问题：

- `http://ymmt.chilfish.top/` 返回 200 且 `CF-Cache-Status: HIT`，不跳 HTTPS，同时无 HSTS。curl 与 `transport_check.py` 两路证据一致。
- `/gallery` HTML 未压缩 2.07 MB，越 Googlebot 解析上限；成员页 / streams / trends / transcripts 普遍 1.0–1.7 MB。内联脚本只有 6.5 KB，体积全在 SSR 出来的 DOM 本身。

其余为中低优先：图片缺 `width`/`height`、`/calendar` 与 `/about` 无 `og:image`、响应头 `Content-Type` 不带 charset、成员页只有 `BreadcrumbList` 缺 `Person`。

### 坑

自写巡爬第一版把 `resp.text` 直接交给 bs4，中文标题长度被算成 3 倍。原因是线上 `Content-Type: text/html` 没带 `charset`，requests 退回 latin-1 解码——这本身也是要修的项（M5）。改成按 UTF-8 解码后数据才干净。

### 未验证

PSI 无 API key 直接 429，claude-seo 的 `pagespeed_check.py` 这条路没跑通。`www.ymmt.chilfish.top` 的 TLS 握手失败疑似本机 DNS 产物（解析到 `28.0.2.188`），需换网络复核。

## 按审计结论修复

改动落在 [research/seo-audit-2026-11-15.md](../research/seo-audit-2026-11-15.md) 第五节的「修复记录」，这里只记判断过程与踩到的坑。

### 中间件

`forceHttps()` 放在 `onRequest` 最前面。线上 `http://` 请求本来就会进 Worker（响应头里有 `x-response-time`），所以不必依赖 Cloudflare 的 Always Use HTTPS 开关。**localhost 要豁免**：`astro dev` 和 `astro preview` 都是 http，不豁免会把自己挡住。

HSTS 只在 `https:` 下发，本地不下发——`max-age` 一旦落到 127.0.0.1，浏览器会把本地开发全转成 https。

charset 只补 `text/*` 且未带参数的；`.md` 路由自己给了 `text/markdown; charset=utf-8`，正则 `^text\/[^;]+$` 不会重复追加。

### 字体

去掉 `@fontsource-variable/noto-sans-sc` 是这轮最大的收益，也是唯一有观感代价的改动：中日文从 Noto Sans SC 换成系统字体（PingFang / Hiragino / Noto Sans CJK / 微软雅黑）。`ui-design/README.md` 原本写的就是「Noto Sans → 系统 sans」，系统栈不算偏离规范，但要接受不同平台的字形差异。拉丁与数字仍自托管，`tabular-nums` 不受影响。

顺带把包从 `package.json` 移除——留着会让下一个人以为还在用。

### 对比度

没有凭感觉调。先算：`#8a8a92` 在侧栏底 `#efe9ee` 上 2.86:1，在卡片白底 3.43:1，都不到 4.5。试到 `#66666f` 才三处全过（4.75 / 5.68 / 5.11），再浅一档 `#6b6b74` 在侧栏只有 4.41。`--sidebar-foreground` 的 64% 混色算出来 4.35:1，差一点点，提到 72% 到 5.48:1。

### 一处初版审计写错了

Lighthouse 的 `image-delivery-insight` 说图片选档过大、浪费 491 KB。查 `configSettings.screenEmulation.deviceScaleFactor` 是 **1.75**——753 CSS px 显示位需要 1318 物理像素，选 1280w 完全正确。`srcset`/`sizes` 在各调用点都写对了，**没有改**。审计文档里那条已改成更正说明，避免下次照着错的方向改。

### 没做的

- 缩略图缓存 4 小时：`scripts/lib/object-storage.ts` 已经写明 Bun 的 S3 写入只能给 `Content-Type`，`Cache-Control` 得在 Cloudflare 加 Cache Rule。代码层改不了。
- `/gallery` 的 1.71 MB island props：查清了体积来源（不是 DOM 铺满，是整份 1,837 行塞进 `props`），但改成「SSR 首屏 + 客户端分页拉取」要新端点与三态，属于功能改动，单独立项 B39。
- LCP trace 与 mobile preset：都要浏览器侧条件，本机复现不了线上网络。

### 验证

- `bun run check`：0 errors，544 tests passed（新增/更新 3 条 SEO 断言）。
- `bun run build` 通过；产物 `@font-face` 101 → 8，woff2 4.29 MB → 430 KB，CSS 390 KB → 282 KB。
- `astro dev` 实跑：`/` 的 `@type` 为 `Organization, WebSite`；`/arale` 为 `Person, Organization, BreadcrumbList`；`/about`、`/calendar` 都有 `og:image`；`Content-Type: text/html; charset=utf-8`；`.md` 未重复追加；两条长标题 56 字。本地 127.0.0.1 不跳转、不下发 HSTS。
- **未验证**：线上 301 与 HSTS 要部署后复查；对比度要重跑 Lighthouse 才能确认归零。

## 会员限定逐字稿的 403

会员限定场次的逐字稿在浏览器里拿不到：页面带访问参数打开正常，但正文请求 `/api/transcripts/<dataset>/<videoId>` 返回 403。

### 原因

`useTranscript` 直接请求 API，没有带页面 URL 上的访问参数，服务端按无权限处理。管理端会话也只在 `/admin`、`/api/admin` 路径校验，其他页面与 API 看不到登录状态。

### 改法

- 正文请求透传访问参数；带参数的响应单独成缓存档，不混进公开缓存。
- middleware 统一识别管理端会话并写入 `locals.admin`，页面与 API 共用同一份访问判定；这类响应同样 `private, no-store`。

### 验证

- `bun run check` 通过。
- 本地实跑：无参数 403；带参数 200；管理端登录后无参数也放行。

## 安全自查

完整记录见 [security-review-2026-11-15.md](../research/security-review-2026-11-15.md)，事故复盘见 [postmortem 006](../postmortem/006-public-r2-member-only-leak.md)。

### 严重：公开桶暴露会限内容

`ymmt-s3.chilfish.top` 是桶级公开域，匿名请求 `<datasetId>/transcripts/<videoId>.json` 与 `archive/<datasetId>/<videoId>.datapack.json` 都返回 200。会限场的逐字稿正文与原始 pack 因此完全绕过页面、API 与访问参数。修复要 WAF block + 私有桶，登记 B43；这次没有改对象存储配置。

### 已落地

- `serializeJsonLd()`：JSON-LD 不再直接 `JSON.stringify` 进 `<script>`，转义 `<`、`>`、`&` 与行分隔符，标题里出现 `</script>` 也闭合不了标签。
- CSP：middleware 对 `text/html` 下发 `content-security-policy`，脚本只允许本站（`'unsafe-inline'` 是主题脚本与 `ClientRouter` 的现状约束），媒体域放行 `img-src` / `connect-src`。dev 模式不发，避免挡 Vite HMR。
- 会员限定鉴权与缓存策略没有改动：错误参数不产生可缓存 200，带参数响应 `private, no-store`。

### 攻防结论

admin 路径对 `//`、`/./`、大小写、百分号编码的变体都不放行（401 / 404）；伪造与过期会话 Cookie 均 401；跨站 POST 403；无 `dangerouslySetInnerHTML`，逐字稿 Markdown 的 `javascript:` 链接由 react-markdown 默认过滤。仍缺速率限制与强访问参数，登记 B44。

- `bun run check`：0 errors，569 tests passed。
- `bun run build` 通过；`astro preview` 下 `/`、`/miyako/stream/<id>?view=transcript`、`/miyako/gallery` 无 CSP 控制台报错，`ClientRouter` 站内跳转正常。

## llms.txt 与对外 JSON Schema

用户指出现有两处不合格：`llms.txt` 内容太薄、第三方 Agent 拿到不知道下一步做什么；接口里写 `yumemita.stream-datapack/v2` 却没有任何地方能拿到 schema。

### llms.txt

对照 [llmstxt.org v2](https://llmstxt.org/)（2026-08-10 修订）与 claude-seo 的 `agentic_check.py` 逐条核过，原实现的问题：

- 「最近场次」20 条全是 `— https://...` 裸地址，不是 `[name](url)`，解析器判 `malformed-link`。
- 成员条目写成 `[名](url) · 534 场 · Markdown 索引：...`，链接后没有 `:`，notes 读不到；而且所谓「Markdown 索引」指向的是 HTML 目录页 `/arale/streams`，属于错误信息。
- `## 约定` 段没有任何链接，是空 H2 段；规范里 H2 只能放文件列表。
- 没写数据口径、参数、接口与免责。

改成 `## 成员` / `## 最近场次` / `## 数据格式` / `## Markdown 视图` / `## 结构化接口` / `## 站点` / `## Optional`。说明段全部放在第一个 H2 之前；条目一律 `- [name](url): notes`。会员限定场次不进「最近场次」——它们的 `.md` 只有标题和封面，列出来是误导。标题里的 ASCII 方括号换成全角，否则会提前终止链接解析。

生成逻辑抽到 `src/lib/agent-llms.ts`（纯函数），配 13 条断言把格式固定下来：首行 H1、摘要紧跟、H2 段只有合规条目、无空段、`## Optional` 收尾。

### 响应头

线上 `/llms.txt` 在 MISS 时既没有 `Cache-Control` 也没有 `Cache-Tag`——`context.cache.set()` 只影响 Workers Cache，不会把浏览器可见的头写出来（`.md` 端点是自己显式写死的）。现在显式声明 `cache-control` 与 `content-signal`，和 `.md` 对齐。

按 v2 提案，所有 HTML 页的 `<head>` 加 `<link rel="describedby" type="text/plain">` 指向 `/llms.txt`（`Layout.astro`，用 `BASE_URL` 拼，避免子路径部署错）。

### JSON Schema

仓库原本只有 `src/types/datapack.ts` 的类型和 `scripts/lib/validate-schema.ts` 的 valibot 校验；后者是校验子集（忽略未知字段、部分字段标 optional），不能当 schema 发布。

新增 `src/lib/json-schema.ts`，输出 draft-07：

- `/schemas/stream-datapack.v2.json` — v2 是 v1 超集，v1 缺的 `chat.authors` / `chat.wordCounts` / `topAuthors[].authorId` 等在 schema 里都是可选，同一份能校验旧 pack。
- `/schemas/transcript.v1.json`
- `/schemas/densities.v1.json`

防漂移靠类型断言而不是文档承诺：每个 `$defs` 的 `properties` 键集合与对应 interface 的 `keyof` 必须完全相等，收敛在一个 `SchemaKeyParity` 类型里。实测故意加一个 `bogus` 字段会直接编译失败并报出字段名。

端点用 `prerender = false`，和 sitemap / llms 保持一致：预渲染产物会丢掉路由里设的响应头，而 `_headers` 对 `Content-Type` 的覆盖在 Workers 静态资源上没有确证。`content-type` 用 `application/schema+json`，`cache-control` 1 小时 + swr 一天。三个 API 的成功响应加 `Link: rel="describedby"` 指向对应 schema。

### 验证

- `bun run check`：0 errors，569 tests passed。
- `bun run build` 通过。
- `astro dev` 实跑：`/llms.txt` 首行是 H1、摘要紧跟、20 条最近场次全部为 `.md` 链接；三个 `/schemas/*.json` 返回 200 且 `application/schema+json`；HTML 页出现 `rel="describedby"`；`/api/packs`、`/api/densities`、`/api/transcripts` 的 `Link` 头正确。
- 用真实响应回灌 schema：`/api/packs/arale/xBZHYX6-bFw`、`/api/transcripts/nonoka/0Oom7elwKMo`、`/api/densities/nonoka?ids=...` 三份全部通过（不要用 `additionalProperties: false` 猜字段，直接拿线上 payload 跑）。
- **未验证**：线上部署后的 `Cache-Control` 与 `Link` 头要重新 curl 确认。

## 部署后按用户实测报告复核线上

用户给了 `ymmt.chilfish.top-20261115T140343.json`（Lighthouse 13.5，目标 `?view=transcript`）。这次没有重装脚本层，直接跑官方的 `runtime.py setup`（自建 venv + Chromium）→ `doctor` 三项 ready，再用 launcher 跑脚本。结论写进 [research/seo-audit-2026-11-15.md](../research/seo-audit-2026-11-15.md) 第八节，待办 B45–B48。

### 工具实际跑了哪些

- `page_checks.py`（首页 / 逐字稿页）：首页 2 条（图片缺尺寸、宽 DOM），逐字稿页 4 条。其中 `canonical-points-elsewhere` 与 `url-uppercase` 是误报——`?view=` 的 canonical 归一到无查询 URL 是有意为之，YouTube videoId 本来就大小写敏感。
- `agentic_check.py`：P0/P1 全 pass，`llms.txt` 合规，真实 404，robots 只有 `*` 组。
- `sitemap_discovery.py --expand`：1 个 urlset、1,837 条、0 无效、0 重复、`lastmod` 全覆盖。
- `render_page.py --a11y-tree`：`mode=rendered`、`is_spa=false`，渲染后 HTML 与原始 HTML 体积几乎一致（253,589 vs 253,941 B）——**逐字稿正文根本没进 DOM**，与 LCP 的 4 秒渲染延迟互相印证。
- `lighthouse_agentic.py --from-json`：3/3，与线上报告一致。
- `pagespeed_check.py`：无 API key，PSI 直接 429（与上一轮同一坑）。CrUX 字段数据仍然缺。

### 三个新结论

1. **首字节 1 秒是真的**。Lighthouse 那份是 10 Mbps / RTT 40 ms / 无 CPU 降速的宽松口径，TTFB 仍报 998 ms。用随机 `cb=` 强制 MISS 复测冷路径：`/` 1.05–1.33 s、单场页 1.60–1.70 s、`/gallery` 0.97–1.19 s。边缘 HIT 后没问题，但 sitemap 的 1,837 条每条在每个 PoP 的第一次都要付这一秒。
2. **LCP 的 4 秒是水合 + 一次 API 往返**。`/api/transcripts` 到 4,457 ms 才发出。正文既不在 HTML 也不在首屏请求里。顺带发现 `?view=transcript` 的 canonical 归一 + `.md` 是 `noindex`，所以正文对搜索引擎和 AI 爬虫都不存在。
3. **上线 CSP 把 Cloudflare Web Analytics 挡了**。`errors-in-console` / `inspector-issues` 双 0 分，最佳实践 92 分的唯一原因。这是本轮改动自己带出来的回归，优先修。

### 复核确认没问题的

### 逐字稿首屏改服务端渲染

`?view=transcript` 时页面先读 R2（`lib/transcript-read.ts`），把 `TranscriptFile` 传成 `initialTranscript`，一路下到 `TranscriptView`；`useTranscript` 拿它当初始状态，并且不再发那次请求。`parseTranscriptFile` 和 R2 载荷原本是两套字段处理（`fileFromPayload` 在 hook 里），顺手收成 `lib/transcripts.ts` 的 `transcriptFileFromPayload()`，服务端与客户端共用。

两个坑：

- 预渲染的正文只属于首屏那一场。`StreamDetailView` 里按 `initialTranscript.videoId === summary.videoId` 过滤，否则切场后会拿错稿。
- 会限场次不能进 HTML（页面按 `!memberOnly` 门控），否则等于把带访问参数的正文写进可缓存文档。

体积账见审计文档：props 里重复的 Markdown 是 54 KB（≈8 KB gzip），净多传约 10 KB，换掉一次 48 KB gzip 的请求和 4 秒的水合等待。

### CSP

放行 Cloudflare Web Analytics 的 beacon。另外发现 CSP 的 host-source 带路径时是精确匹配——本地 `PUBLIC_R2_BASE=http://127.0.0.1:9000/ymmt-data` 会让所有缩略图被 `img-src` 挡掉（线上没路径所以看不出来）。`assetSource()` 统一收敛到 origin，配一条单测。

### 可访问性

搜索按钮去掉 `aria-label`、改用 `sr-only` 文案；目录项与「回到顶部」加 `min-h-6`；切场按钮的 `aria-label` 从 `较新一场：` 改成 `较新：`。

最后一条靠 axe 的 token 比对才解释得通：`较新一场` 会被当成一个词，可见文本 `较新` 不在里面，所以 `label-content-name-mismatch` 报错；而「较早」同样的写法却通过了。以后这类标签优先让可见词独立成形（空格或标点隔开），别直接拼在词中间。

## 构建期 404 / 500 的 `Astro.request.headers` 警告

`bun run build` 在生成 `/404.html`、`/500.html` 时打警告：预渲染页读了 `Astro.request.headers`。这两个页面和 `Layout` 都没碰 `request`，来源是 middleware：Cloudflare 适配器 `middlewareMode: 'classic'`，预渲染页在构建期也会跑一遍 `onRequest`，而 `hasAdminSession()` 里的 `context.cookies.get()` 内部会读 `request.headers`（`astro/dist/core/cookies/cookies.js` 的 `#parse()`）。

改成预渲染时直接跳过会话解析（`context.locals.admin = context.isPrerendered ? false : ...`）。静态 HTML 本来就不带会话状态，管理端路径又全是 `prerender = false`，行为不变。
