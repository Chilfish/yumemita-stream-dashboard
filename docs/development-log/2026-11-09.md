## 直播预定与日历：直播中只保留开播后 1 小时

### 操作

- `isLive` 的窗口从「预计时长 + 120 分钟宽限，上限 12 小时」改为「开播前 15 分钟到开播后 1 小时」。
- 结束时间不可预测，不再读 `expectedMinutes` 推算；超过窗口且未入库时状态落到 `pending`（待补录），入库后变 `done`。
- 有 `scheduled_at` 时不再用 `lastLiveAt` 延长直播中；只有缺少精确时间的事件才以 `lastLiveAt` 为起点，同样最多 1 小时。
- `直播预定`（`DayTimeline`）和日历共用 `deriveCalendarEventState`，两处同时生效；`expected_minutes` 字段保留但不再参与状态派生。

### 验证

- `bun run test`：427 tests 通过（`calendar.test.ts` 30 条，新增开播窗口、1 小时后待补录、`lastLiveAt` 回退用例）。
- `bun run lint`：0 errors（27 个既有 warning）。
- `bun run build`：通过。
- 本地 `scheduled_streams` 为空，无法手工走查「直播中 → 待补录」切换；状态逻辑由单测覆盖，页面渲染路径未变。
- 文档同步：[live-calendar.md](../planning/live-calendar.md) 状态派生表与状态收敛、FR-CAL-002 验收、`data-model.md` 字段说明。

### 未完成 / 注意

- 若实际开播明显晚于 `scheduled_at`，超过 1 小时后会显示「待补录」；这是按需求接受的取舍。
