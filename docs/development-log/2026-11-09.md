## 日程表只保留未来场：已入库行删除、重复行合并

### 操作

- `scheduled_streams` 改为只保留还没入库的未来场：`ingest` 写完后调用 `pruneMatchedSchedules`，按 `video_id` → 链接里的 video id → 成员 + JST 日期 + 时段删除对应日程，不再写 `superseded_by`。
- 删除 `superseded_by` 列（迁移 `0009_drop_superseded_by.sql`），读取路径改为只按 `streams` 的 video id 判断 `hasStream`，链接里的 video id 同样生效。
- 统一主键规则：已知日期 + 时段时 `event_key = manual:<date>-<slot>`，`yt:<videoId>` 只用于时间未知的自动行。管理端只传 `url` 不再推导 `videoId`、也不改主键；PATCH 改期时自然键跟着改，显式 `id` 行保持原键。
- `planScheduleConsolidation` / `normalizeScheduleKeys`：`yt:` 行拿到日期/时段后改名为自然键；已有同日同时段的手工行或同视频手工行时，合并为自然键一行（自动行补 `videoId` / 标题 / 链接），不再保留重复的 `yt:` 行。
- 每日同步改为逐条 upsert：先按 `eventKey`、`videoId`、链接里的 video id 找已有行，就地更新而不是另插一条；同步后再归一，避免手工行被自动行挤成第二行。
- 读取侧 `buildCalendarEvents` 按有效 video id 合并日程行；`matchSchedulesToStreams` 也认链接里的 video id，带链接的手工行不会因为缺少 `date`/`slot` 而漏匹配。
- 新增 `bun run schedule:prune`（`scripts/prune-schedules.ts`）：默认 dry-run，`--apply` 写库，`--dataset` 可限定成员；环境沿用 `LOCAL` 开关。
- 每日任务 `syncScheduleFromChannel` 同步后自动归一重复行，日志输出「归一重复 N」。标题不参与匹配，避免「ゲーム」「朝活」这类占位标题误伤。

### 验证

- `bun run test`：444 tests 通过（新增 `schedule-match.test.ts` 11 条，`schedule.test.ts` 链接解析与主键规则，`calendar.test.ts` 链接认领与重复合并）。
