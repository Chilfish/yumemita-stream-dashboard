## 逐字稿附录字幕默认折叠

### 操作

- 动机：逐字稿的主体是分析正文，附录中日对照动辄几千行；默认铺开会把正文压在很上面，读者也不一定需要字幕。
- `transcript-appendix.tsx` 用 coss `Collapsible` 包住字幕列表：附录标题与格式说明仍留在正文末尾，字幕列表默认收起，触发器写「展开字幕（N 条）」/「收起字幕」。
- 语言开关（`SegmentedControl`）从页头摘要移到展开区顶部，收起时不再占用一行；展开后才挂载字幕 DOM，收起后节点全部卸载。
- 目录里的附录小节指向已卸载的节点：`transcript-view.tsx` 的目录点击改为 `navigateToHeading()`，命中附录小节时先展开，再滚动。
- 滚动时机：`CollapsiblePanel` 的高度过渡是 200ms，过渡中途调用 `scrollIntoView` 会被浏览器按当时的文档高度截断（实测落点偏 318px）。改为监听面板 `getAnimations()`，等过渡开始并结束再滚，800ms 兜底。
- 文档同步：[research/long-transcript-rendering.md](../research/long-transcript-rendering.md) 第七、八节与方案表、[engineering/code-map.md](../engineering/code-map.md)、`requirements-spec.md`（`AC-TRANSCRIPT-001`）、`CHANGELOG.md`。

## 同日同时段多场日程（序号键）

### 操作

- 动机：一位成员同晚播两场（本地库里 `yuno` 的 `manual:2026-11-10-late` 与 `manual:2026-11-10-late-2`）。原来的键策略把「同日同时段」当唯一：POST 不带 `id` 时 `onConflictDoUpdate` 会静默覆盖前一场，而管理页根本不发 `id`，等于没有第二场入口。
- 键语法：`manual:<date>-<slot>` 是第 1 场，`-2` / `-3` 顺延。`parseManualEventKey` 解析序号（拒绝 `-1` 与 `-02` 这类非规范写法），`scheduleEventKey` 反向生成；`isNaturalEventKey` 改为复用解析结果，序号行也算自然键。
- POST：新增 `resolveCreateKey`，无显式 `eventKey` / `id` 时按同成员同日期同时段查一遍，`planScheduleEventKey` 判定同一场则复用键、不同场则取空序号。同场判定 `isSameScheduleOccurrence`：两侧都有标题比标题，否则比 `scheduledAt`。
- PATCH：自然键行改期时保留原名序号（`-late-2` → 新日期仍是 `-2`）；目标键上如果是另一场（video id 不一致）返回 409，不再静默合并。
- 自动同步 `upsertScheduleEntries`：不再无条件按自然键认领目标行，改为「未认领 + 视频 id 相容 + 开播时间最近」。原实现里 `byKey` 命中就更新，同槽第二条自动行会把手工行覆盖掉，`occupant` 守卫永远走不到。没有可认领行时用 `freeScheduleEventKey` 顺延序号，而不是退回 `yt:`。
- 对账 `planScheduleConsolidation`：手工行按 `date:slot` 分桶并记录认领状态，`yt:` 行先按 video id、再按最近时间挑未认领的手工行；没有可合并目标时改名为该时段的空序号。原来的 `naturalTargets` 是 Map 后写覆盖前写，两条同槽行会合并进随机一条。
- 管理端列表：`itemTimeLabel` 对序号 ≥2 的行补「· 第 N 场」，否则同槽两行都只显示「晚上」无法区分。
- 清理：删除不再使用的 `resolveEventKey`（API 改为 `resolveCreateKey`）。
