## 平台未保留回放被误判为「直播尚未结束」

`6CRIOtWb-Og`（2024-05-03 宮永ののか「E-999」）没有弹幕，`chat.total` 为 0。

### 核查

- pack 里 `video.hasLiveChatReplay: false`；`data/missing-danmaku/nonoka.txt` 一直为空，这场没进过补抓清单。
- 带 cookie 请求 watch 页：`playability: OK`、`isLiveNow: false`、`endTimestamp` 有值、`isReplay: null`，
  页面没有 `liveChatRenderer`，`availabilityMessage` 为 `Live chat replay is not available for this video.`。
- 同日其他场次（`vcSGOhs9qCc`、`b_ngxOnLq7o`）在同样条件下返回 `isReplay: true` 且带 reload token，排除登录态 / bot 检查干扰。
- 带 cookie 的 `yt-dlp -J`：`subtitles` 里没有 `live_chat`（对照组有），确认平台侧没保留这份字幕。

### 根因

`collectReplay()` 只用 `liveChatRenderer.isReplay` 判断有没有回放。这类场次没有 renderer，`isReplay` 是 `null`，
于是走到 `status = 'live'`，`data danmaku` 报「直播尚未结束，实时采集请用 fetch:live-chat」，
一场 2024 年的回放被当成还在直播，也没写 `chat-unavailable.txt`，每轮都会被当成失败重试。

`classifyWatchStatus()` 本身判对了（`ended`），错在回放采集没有复用它。

### 改动

- `scripts/lib/innertube-live.ts`：新增 `isChatReplayUnavailable(status)`，只认 `availabilityMessage` 里的
  `live chat replay is not available/unavailable`，`isReplay === true` 时恒为 false。
- `scripts/lib/live-chat-collect.ts`：无 continuation 时按 `isReplay === true || isChatReplayUnavailable()` 判 `no-replay`；
  命中平台未保留时给 `result.reason = 'chat-replay-unavailable'`。
- `scripts/commands/data/danmaku.ts`：auto 模式拿到该 reason 就不再回退 yt-dlp（字幕同样不存在），直接写 `chat-unavailable.txt`。
- `scripts/commands/data/live-chat.ts`：实时采集改走回放且平台未保留时，日志不再说「回放未完成，重跑会续翻」。
- 文档：`docs/data/chat-events.md` §10 补「平台未保留回放」一行。

### 验证

## 单场重抓并覆盖（`data refetch`）

### 背景

重抓一场的完整链路要手工跑五步：`data fetch --force` → 本地 `db ingest` → 线上 `db ingest`
→ `db verify` → `publish data` → `publish purge`。中间漏一步就会出现「本地新、线上旧」
或「archive 更新了但索引没刷新」。现在收敛成一条命令，只给链接。

```bash
bun run ymmt data refetch "https://www.youtube.com/watch?v=1dGnP_rXgW0"
bun run ymmt data refetch 1dGnP_rXgW0 --no-online   # 只改本地 pack / 本地库
```

### 设计

- 视频 ID 从 `watch?v=` / `youtu.be/` / `/live/` / `/shorts/` 解析，也接受裸 11 位 ID。
- dataset 先按 `data/<id>/<videoId>.datapack.json` 所在目录推断；本地没有 pack 时用
  yt-dlp 元信息里的 `channel_id` 匹配 `data-sources.json`，避免先记住成员。
- 复用现有进程内入口：`runFetch`（`--no-publish` 关闭它自己的自动发布）、`runIngest`、
  `runVerify`、`runPublishData`、`runPurge`。
- 默认在线（`.dev.vars` 的 `DATABASE_URL_ONLINE`）：本地 ingest 后切到线上环境再写 Neon、
  刷新索引并 purge，结束后恢复环境。`--no-online` 只写本地库并重算本地 manifest / insights。
- 线上环境切换原来藏在 `publish sync` 内部，抽到 `scripts/lib/online-env.ts`，两处共用。

### 顺带修掉

- `data fetch` 的 `--no-publish` / `--no-build` / `--no-restore` / `--no-cookies` 映射错误：
  commander 把 `--no-x` 存成 `x: false`，原代码却读 `ctx.flag('noX')`，导致 `--no-publish`
  仍然会自动 ingest + 发布。
- `db verify --ids` 的 `dataset_insights` 对比用了过滤后的 pack 子集，必然报「与重算结果不
  一致」；改为始终用全量本地 pack 重算，`publish sync` 的定向对账也一并恢复正常。

## scripts 收敛为统一 CLI（backlog B36）

44 个顶层脚本各自手写 `parseArgs` / `USAGE`，40 条 npm scripts，没有共享日志与退出码约定；
`scripts/` 也不进 typecheck。改成单一入口后，命令树、帮助、日志、JSON 输出与退出码只有一处实现。

### 结构

- `scripts/cli.ts`：唯一入口，只做总装（`groups` + `rootCommands`）。
- `scripts/commands/<group>/<command>.ts`：一个文件一个 `CommandSpec`；同目录 `index.ts` 汇总成 `CliGroup`，
  `commands/index.ts` 汇总全部分组，`cli.ts` 不再堆 import。
- `scripts/lib/cli/`：`runtime`（commander 子命令、帮助、信封、退出码）、`logger`、`envelope`、`exit`。
- `scripts/oneoff/`：一次性补丁保持原有用法，不注册子命令、不进 `package.json`。
- `tests/`：所有 `*.test.ts` 从 `src/` 与 `scripts/` 集中过来，目录镜像被测源码。

### 契约

- `--json`：stdout 只输出一行 `{ok,command,data,error,meta}`；人读日志一律走 stderr。
- 退出码：0 成功 / 1 运行期失败 / 2 用法错误 / 3 配置缺失。
- `describe --json`：完整命令树，供 agent 自举。
- `--dry-run`：全局只读开关；命令自己保证不写库、不写对象存储、不改文件。
- 每位命令开工前打印目标环境（沿用 `describeEnvironment()`），不必等跑完才知道连的是本机还是线上。

### 顺带修掉的问题

`scripts/` 首次纳入 `tsc` 后暴露的既有缺陷：

- `dev-services.ts` 调用不存在的 `readEnvValue()`，改用 `parseEnvContent()`。
- `object-storage.ts` 的 `Credentials` 没有导出，`dev-silo.ts` 却从它导入。
- `schedule-match.ts` 构造 `CalendarEventInput` 时漏了 `participantIds`。
- `dataset-manifest.ts` 复制了一份 `StreamSummary`，改为直接复用 `src/types/dataset.ts`。
- `datapack.ts` 的本地 `ChatRecord` 缺 `rendererId`。

## 会员限定逐字稿：显式标记并在发布链路跳过

### 背景

`publish transcripts` 对 5 篇会员限定稿报「manifest 里没有 videoId」。这些场次不在 manifest / DB，
但正文此前已进入 `content/transcripts`；发布既无法校验归属，也会把它们当普通稿上传。

### 改动

- `TranscriptFrontmatter` 新增 `membersOnly`，`normalizeFrontmatter` 解析 `true / 1 / yes`。
- 新增 `isMemberOnlyTranscript()`：字段为真，或 `tags` 含「会员限定 / 会限」即视为会员限定。
- `transcript import`：命中会员限定即跳过，并删除 `content/transcripts` 里的本地副本（`--allow-member-only` 才放行），不再依赖 manifest 是否收录。
- `publish transcripts`：会员限定稿不上传、不进索引、不写 `transcripts` 表，日志按「保留归档」计数。
- `syncTranscripts`：跳过会员限定稿，并删除该 dataset 下对应的旧元数据行。
- 给已有 5 篇会员限定稿补 `membersOnly: true` 后从 `content/transcripts` 删除。
- 文档：`content/transcripts/README.md`、`docs/data/adding-data.md`。

### 验证

- `bunx vitest run tests/lib/transcripts.test.ts`：通过。
- `bun run ymmt publish transcripts --no-upload --force`：会员限定 5 篇跳过，无 manifest warning。
