## VSTATS 不再按 14 天窗口放弃

问题：`daily-update` 每个成员都打印一长串「已放弃：缺 VSTATS 已超过 14 天」，以 ritsu 为例 280 场。
`planDataset` 超过 `vstatsGapDays = 14` 后把场次记为终态，再也不尝试。

### 核查

- 这些 ID 都在本地 `streams` 表里，只是 `vstats_views / avg_concurrent / max_concurrent` 为空。
- 直接请求 `https://www.vstats.jp/video/<id>`：VSTATS 对这些频道的收录从 2026-08 上中旬才开始，
  更早的场次统一返回 `200 + 5 字节 error`（抽 24 条，除 503 限流外都是这个结果）。
- 但确实有能补却没补的：`yuno/mn4Jjd7KdXY`（2026-09-22）页面 31KB、有完整统计，
  只因超过 14 天被跳过。旧的 `--force` 路径会连弹幕 / 评论一起重抓，成本太高，
  没人会为了补一个 VSTATS 数字去跑它。

### 改动

- 新增 `scripts/lib/vstats.ts`：把单场页解析与派生比值从 `stream-datapack.ts` 抽出来，
  两处共用同一套口径（`chatPer1000AvgViewers` / `likesPer1000Views` / `vstatsVsYtdlpViews`）。
- 新增 `scripts/backfill-vstats.ts`：只请求 VSTATS 单场页，写回 pack 的 `vstats` 与 `derived`，
  同步 upsert manifest；不重抓 meta / 弹幕 / 评论 / 媒体。
  - 候选取自 manifest：`vstatsViews` 为空且 `availability = public`；随机轮转，旧场次不会被饿死。
  - 5 字节 `error` 记「未收录」；5xx / 超时记临时失败并重试一次；单场默认间隔 300ms。
  - 每轮默认 20 场（`--limit`），避免撞 VSTATS 限流。
- `scripts/lib/update-plan.ts`：删掉缺 VSTATS 的 `forceIds` / `expiredIds` 分支与 `vstatsGapDays`。
  缺 VSTATS 只由补抓脚本处理，不再出现在「已放弃」里；缺弹幕的 7 天窗口保持原样。
- `scripts/daily-update.ts`：每个成员在抓取后跑一次 `backfill-vstats`，默认 20 场，
  补到的 ID 合并进 `changedIds`，后面的 ingest / `publish-data --assets-only --ids` 会自动带上。
  新增 `--vstats-limit` 与 `--no-vstats`；`--no-publish` / `--dry-run` 跳过补抓。
- 文档：`scripts/README.md`、`docs/data/data-progress.md`、`docs/engineering/deployment.md`、`README.md`。
