# 2026-11-18

## Worker 层拦截 AI 训练抓取机器人

线上日志里 Meta 的 `meta-externalagent/1.1` 高频巡爬 `/arale/stream/*`，每次都触发一轮请求期 SSR（`outcome: exceededCpu`）。robots.txt 对这类 bot 只是建议，改成在 Worker 入口按 UA 直接 403。

### 做法

`src/worker.ts` 在交给 `@astrojs/cloudflare/handler` 之前先过 `isBlockedBot()`（`src/lib/bot-filter.ts`）：命中就返回 20 字节纯文本 403，不跑 Astro、不查库、不占 CPU 配额。

清单按厂商分档维护，参考 [ai-robots-txt/ai.robots.txt](https://github.com/ai-robots-txt/ai.robots.txt)（2026-11 版）：

- Meta：`meta-externalagent` / `meta-externalfetcher` / `meta-webindexer` / `FacebookBot`
- OpenAI、Anthropic、Google、Apple、Amazon：只拦训练档（`GPTBot`、`ClaudeBot`、`Google-Extended`、`Applebot-Extended`、`Amazonbot` 等）
- 国内厂商：`Bytespider`、`ChatGLM-Spider`、`ERNIEBot`、`DeepSeekBot`、`QwenBot`、`TongyiBot` 等
- 公开数据集 / 图库：`CCBot`、`img2dataset`、`LAION*`、`ImagesiftBot`
- 爬虫框架与爬取服务：`Scrapy`、`Crawl4AI`、`FirecrawlAgent`、`ApifyBot`、`Lightpanda`

**刻意放行**搜索索引类（`OAI-SearchBot`、`Claude-SearchBot`、`PerplexityBot`、`ChatGPT-User`、`Googlebot`、`Bingbot`、`Applebot`）：拦掉它们等于从 AI 回答的引用里消失，和这次要解决的「被高频巡爬打爆 CPU」不是同一件事。

`public/robots.txt` 同步列出同一份清单——robots.txt 只是给守规矩的 bot 看的，Worker 阻断才是兜底。

### 验证

```bash
bun run check      # 0 errors（575 tests，其中 bot-filter 4 条）
bun run build
bun run preview    # localhost:4321
```

- `curl -A '<meta-externalagent UA>' /arale/stream/YsUueSaJHIo` → `403`，body 20 字节，带 `x-robots-tag: noindex, nofollow`
- 同 URL 用 Googlebot 与普通 Chrome UA → `200`，329,646 字节完整 HTML

### 未验证

线上生效需要重新部署；`/robots.txt` 由静态资产层直出，不经过 Worker，所以那份文件只影响守规矩的 bot。

### 备注

静态资产（`ASSETS`）不经过 `src/worker.ts` 的 `fetch`，拦截只覆盖 SSR 与 API 路径，这是预期行为——被拦的正是会跑 SSR 的那些请求。
