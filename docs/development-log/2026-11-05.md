## `bun run dev` 一条命令拉起本地服务

**做了什么**

- `scripts/dev.ts`：`dev` 的新入口。先 `ensureDevServices()`，再用 **Node** 启动 Astro（Bun 运行时会让 miniflare `dispatchFetch` 报 `ECONNREFUSED`），参数原样透传。
- `scripts/lib/dev-services.ts`：编排本地服务。
  - Postgres：按 `PG_CTL` / `PATH` / `where` / `scoop prefix` / `%SCOOP%` / `Program Files` 找 `pg_ctl`，按 `PGDATA` / Scoop `persist\postgresql\data` 找数据目录；`pg_ctl status` 判定后按需 `start`。
  - 建库 + `drizzle/` 迁移；缺 `.env.local` / `.dev.vars` 时补写本机 `DATABASE_URL` 与 `NEON_HTTP_ENDPOINT`。
  - 代理：`/health` 校验后复用；不一致时报出占用 pid。Windows 用 `cmd /c start "" /b` 脱离父进程树，macOS / Linux 用 `detached: true`。
- `scripts/dev-db.ts` 改为复用同一套函数，只保留 CLI。
- `scripts/dev-db-proxy.ts` 的 `/health` 增加 `pid` 与 `host`，便于复用前核对目标库。
- `package.json`：`dev` 改为 `bun scripts/dev.ts`；`dev:db` / `dev:db:proxy` / `dev:seed` 保留。
- 文档：重写 [local-database.md](../engineering/local-database.md) 的启动 / 停止 / 排查，同步 README、AGENTS.md、development.md、`.env.example`、backlog B17。

**为什么**

- 之前要开两个终端（代理 + Astro），重启电脑后容易忘；这次页面的 `Network connection lost` 就是因为代理没起，Neon HTTP 驱动连不上 `/sql`。
- 关掉 `astro dev` 不该顺手停掉数据库：Postgres 与代理作为独立后台进程常驻，重复启动只复用。

**验证**

- 冷启动（Postgres 与代理都停掉）后 `bun run dev`：依次输出 `[dev] 启动 Postgres…` → `代理就绪（pid 916880）` → Astro `ready in 9979 ms`，`/nonoka` 与 `/` 均 200，代理 `queries` 递增。
- 第二次 `bun run dev`：输出 `Postgres 已在运行` / `复用已运行的代理（pid 925604）`。
- `kill_shell` 杀掉整棵 dev 进程树（含 taskkill /T）后：5432 与 4444 仍在监听，`/health` 返回 `pid 925604`，Astro 端口已释放。
- `bun run lint`：0 warning / 0 error。

- macOS / Linux 的 `pg_ctl` 查找与 `detached` 分支未在真机验证，只按路径优先级实现。
