## `db pull`：线上库增量同步到本机

### 背景

本机库只能靠 `db ingest` 从本地 pack 重建。线上直接改出来的行（日程、insights、线上重灌的明细）带不回本机，对账时两边长期漂移。

### 决定

- 数据方向是「线上 → 本机」，与 `publish sync` 相反：线上是权威源，本机按线上对齐。
- 判定不看时间只看 `content_hash`：同一份 pack 的 hash 相同即内容一致，跳过整场明细传输；hash 不同或任一侧缺失则整场覆盖。
- 本机独有场次默认删除（`--keep-local` 保留），`scheduled_streams` 每次整体覆盖，`dataset_insights` 整行覆盖，`authors` 只补缺失。
- 写入目标必须是本机库：`DATABASE_URL` 不是 localhost 时直接报 `NON_LOCAL_TARGET`，避免把线上行写回线上。
- 本机自增 id 重新分配，不沿用线上 `streams.id` / 子表 `stream_id`。
- `--full` 用于 ingest 逻辑变更后刷新：hash 相同不代表旧代码灌的明细一致。

### 改动

| 文件 | 改动 |
| --- | --- |
| `scripts/lib/stream-sync.ts` | 纯函数 `planStreamPull`：`missing` / `changed` / `forced` 判定与本机独有集 |
| `scripts/commands/db/pull.ts` | 命令实现：一场一事务覆盖场次与子表，逐字稿 / insights / 日程 / 作者同步 |
| `scripts/commands/db/index.ts` | 登记 `db.pull` |
| `tests/scripts/lib/stream-sync.test.ts` | 8 条判定用例 |
| [cli.md](../engineering/cli.md) | 命令表补 `db pull` |

### oxlint 配置调研

按 [官方配置文档](https://oxc.rs/docs/guide/usage/linter/config.html) 与本仓实测：

- `plugins` 会覆盖默认集合。原配置 `["react", "typescript", "oxc"]` 顺带关掉了默认的 `unicorn`；这次维持关闭（开启后 correctness 类别会新增 14 条 `no-new-array` / `no-useless-fallback-in-spread`，属于独立的小重构），补上 `import`（当前 0 命中，能拦住写错的路径）。
- `categories` 默认只开 `correctness`。实测 `suspicious` 除 `react/react-in-jsx-scope` 的 2060 条假阳性外只剩 13 条真问题（`no-shadow`、`no-unmodified-loop-condition`、`preserve-caught-error`、React Compiler 的 effect 依赖），先不开；`perf` 161 条、`pedantic` 888 条，噪声主要来自脚本里有意为之的 `no-await-in-loop` 与 `eqeqeq`。
- `jsx-a11y` 22 条，集中在自定义 `role` 和没有 label 的控件，需要逐个人工判断，单独作为后续任务。
- 类型感知规则（`typescript/no-floating-promises` 等）需要额外安装 `tsrs` 或 `oxlint-tsgolint`；当前 `astro check` + `typecheck:scripts` 已覆盖类型错误，暂不引入。
- `settings.react.linkComponents` / `settings.jsx-a11y.components` 可以把站内的 `<Link to>` 映射成 `<a>`，等真正启用 a11y 规则时再加。
