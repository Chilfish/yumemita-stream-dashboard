## 脚本层数据库重复读写

**做了什么**

- `scripts/daily-update.ts`：成员状态从「每个成员 2 条查询」改成一次 `inArray` 取回全部 `streams` 与 `dataset_insights`，用 `runBatch()` 合并为 1 次 HTTP 往返。
- `scripts/ingest-db.ts`：
  - `syncTranscripts()` 先读该成员的 `transcripts.content_hash`，内容未变直接跳过，不再每次 upsert 全部稿件。
  - insights 过期判断把 `dataset_insights` 与 `count(*)` 合成一条查询，每成员少 1 条 SQL。
- `src/db/queries/dataset-totals.ts`：`computeDatasetPublicTotals()` 改为窄 SQL 聚合。`streams` 只取汇总列；词频 / 作者在 SQL 里 `sum + group by`；评论 / 贴纸按场聚合；`stream_details` 只取 badges / hashtags / emojiKinds 与 `density->'perMinute'`。不再还原 pack，也不再加载 paid_events / comments 的完整明细。
- `src/db/schema.ts` / `drizzle/0005_magical_diamondback.sql`：新增 `streams.paid_share_pct`；`ingest-db` 写入，`buildPack()` 与汇总复用精确值。旧行没有值时按每分钟序列近似。
- `src/db/queries/packs.ts`：删除不再使用的 `getDatasetPackSet()` / `getDatasetPacks()`；`buildPack()` 回填 `paidSharePct`。
- `scripts/lib/schedule-sync.ts`：未来场从逐条 upsert 改为一次多行 upsert；缺时刻时用 `coalesce` 保留旧值。
- `scripts/verify-db.ts`：只取对账需要的 5 列；4 条 group by 放进同一个 `runBatch()`。
- `scripts/publish-transcripts.ts` / `scripts/lib/publish-state.ts`：内容未变时复用上次 `contentUpdatedAt`，避免 CI 每天 checkout 改 mtime 导致全部逐字稿重传；索引 `generatedAt` 改成条目里的最新时间，内容不变时索引也不变。
- 文档：更新 [db-optimization.md](../planning/db-optimization.md) §8，登记 backlog B20。

**为什么**

- 每日任务只新增 1 场时，仍会按成员逐条查状态、全量 upsert 逐字稿、全量重算 insights，并在 `computeDatasetPublicTotals()` 里把同一个 dataset 的 `streams` 读两遍。
- `publish-transcripts` 把文件 mtime 写进对象内容，CI 每次 checkout 都会改 mtime，导致 13 篇正文与索引每天重传。
- 上一轮数据库优化只覆盖请求期读路径，离线脚本不在范围内。

**验证**

- `bun run check`：astro check 0 error、323 tests 通过、oxlint 0 warning。
- 用本地 pack 的全量 `aggregateDataset()` 与新 SQL 汇总逐字段比较：除 `topWords` 的低频词尾差外全部一致；`paidSharePct` 由新列恢复为精确值。
- 本地执行 `bun run db:migrate`（`0005_magical_diamondback.sql`）与 `bun scripts/refresh-public-totals.ts`；arale / miyako / nonoka / ritsu 的 `bun run db:verify` 均为 0 problems。
- 本地 `db:verify --dataset yuno` 曾在该成员 ingest 仍在运行时执行，`442/443` 与 `stream_authors` 差异属于中间状态；等该轮 ingest 完成后重跑再确认。

**未做**

- 任一 pack 变化仍触发该成员的全量 insights 重算，但现在只读汇总列与 SQL 聚合结果，不再拉完整 pack 明细；`aggregateDataset()` 的分位数与极值仍不可增量合并。
- `topWords` 与本地全量聚合有极小尾差：ingest 只把 `count >= 3` 且非停用词的词写入 `stream_words`。
- `daily-update` 仍按成员分别 spawn `ingest-db` / `publish-data`，两份脚本各自 parse 一遍本地 pack 未合并。

## 全本地开发开关 LOCAL=1（SILO 替代 R2）

**做了什么**

- 新增 `LOCAL=1` 总开关：`scripts/lib/local-config.ts` 统一定义本地默认值（数据库、`/sql` 代理、S3 端点、桶名、凭据），并与 `bun` / S3 客户端解耦，便于单测。
- `scripts/lib/object-storage.ts`：`readCredentials()` 在本地模式返回 SILO 凭据（`S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`，默认 `http://127.0.0.1:9000` 与 `silo-admin`）；`createObjectStore()` 改用可配置 endpoint 与 path-style；`remoteBase()` 在未设 `DATAPACK_BASE` 时返回本地桶地址。
- 发布进度按目标分开：`publishTarget()` 给本地记录加 `local/` 前缀，文件也分成 `data/.publish-state.local.json` 与线上 `.publish-state.json`。本地跑一次不会让下一次 CI 因 target 变化全量重传。
- 新增 `scripts/lib/dev-silo.ts`：启动 / 复用 SILO（MinIO 维护分支，兼容 `silo server` 与 `MINIO_*`），自动建桶并设置匿名只读；新增 `bun run dev:storage` 只准备对象存储。
- `scripts/lib/dev-services.ts`：`LOCAL=1` 时强制本地数据库与端点；启动 SILO；把 `LOCAL=1` 与本地 `DATABASE_URL` upsert 到 `.env.local` / `.dev.vars`。
- `astro.config.mjs`：`LOCAL=1` 时用 `vite.define` 把 `import.meta.env.PUBLIC_R2_BASE` 指向本地桶；派生地址不落文件，关掉开关即回到线上值。

- `scripts/dev.ts`：新增 `--local`，等价于 `LOCAL=1` 并写回 `.env.local`，避免 Windows 下临时设环境变量。

## 本地数据同步到线上

**做了什么**

- 新增 `bun run sync:remote`：只读 `.env` 的线上 `DATABASE_URL` / `R2_*`，忽略 `.env.local` 与 `.dev.vars`，子进程强制 `LOCAL=0`；`.env` 指向本机时拒绝执行。
- 默认**只新增**：先查线上 `streams.video_id`，只把本地缺失的 ID 传给 ingest / verify / publish；候选窗口默认最近 7 天开播的 pack（`video.startedAt`），历史场次视为已同步。`--update-existing` 才按 hash 刷新旧场次。
- `ingest-db` 支持 `--ids` / `--new-only`；`publish:data` 支持 `--ids`，只上传指定场次的封面 / 表情 / archive，索引仍刷新。
- `daily-update` 把本次 `newIds + forceIds` 直接写成 `daily-changed-<id>.txt`，传给 ingest 与 publish；没有明确 ID 时退回最近 7 天改过的 pack，不再每次扫全量。
- 默认先跑 `db:migrate`（线上 `0005_magical_diamondback.sql` 已应用），ingest 后跑 `refresh-public-totals`；`publish:data` 新增 `--adopt-remote`，本地没有进度记录时按远端大小对齐。
- 逐字稿独立处理：数量有差异时用空 ID 文件只同步 `transcripts` 元数据，不碰 pack。
- `verify` 默认只警告、不阻塞发布（`--strict-verify` 才中止）。
- `scripts/lib/env.ts` 抽出 `parseEnvContent()` / `readEnvFile()`，`loadEnvFiles()` 复用同一份解析；新增单测。

**验证**

- `bun run check`：0 error / 0 warning，342 tests 通过。
- dry-run：候选 13（最近 7 天开播）、新增 0、逐字稿数量差异 1 个成员（ritsu 7/2）。
- 实际跑一次默认 sync：migrate no-op；上传 5 篇新逐字稿与索引（18 条）；ritsu 只执行 `0 packs` + 5 篇逐字稿元数据，没有读写任何已有 stream；purge 因缺少 `PURGE_TOKEN` 跳过。
- 封面修复：`ritsu/thumbs/wCdd1XmISYQ.*` 与 `yuno/thumbs/yyogJXm09cU.*`、对应 archive 均恢复 200。
- 按大小对齐实测：临时移除本地发布进度后，对 SILO 跑 `publish:data --dataset nonoka --assets-only --adopt-remote`，按远端大小跳过 1,270 个封面 / 变体 / 表情与 268 个 pack，只上传 21 个大小不同的 pack。
