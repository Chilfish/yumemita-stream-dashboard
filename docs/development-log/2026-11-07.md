## cookie 缓存每次运行重新导出：修复旧 jar 撞 bot 检查

### 现象

yt-dlp 升级到 2026.10.26 后，`--cookies-from-browser firefox` 能读到元信息，
但用脚本缓存的 `~/yt-cookies.txt` 走 `--cookies` 却稳定报
`Sign in to confirm you're not a bot`。同一场 `c_T1QlWWsOE` 用浏览器 cookie 成功，
用缓存 jar 连续失败。

同时 `--list-formats` 只列出 360p，并提示 `web_embedded` 缺少 URL、可能是 SABR-only
实验。本仓库只抓元信息 / 弹幕 / 评论，不下载音视频，这条警告不影响流水线。

### 根因

`scripts/lib/yt-cookies.ts` 的设计是「缺失时导出一次，之后永久复用」。
对比缓存 jar 与同一时刻的导出：

- 缓存 47 条，缺少 `.youtube.com` 的 `SID` / `HSID` / `SAPISID` / `APISID` / `SSID` /
  `__Secure-1PSID` / `LOGIN_INFO`，只留下 `__Secure-3PSID`；
- 新导出 57 条，主登录 cookie 齐全。

yt-dlp 的 `--cookies` 写回不会删 cookie（实测 57 → 57），所以问题不是工具破坏文件，
而是缓存长期没有重新导出：旧版本代码或浏览器轮换 `__Secure-*PSIDTS` 之后，
文件里的会话已经不可用，而 YouTube 对文件 cookie 不做浏览器那种续期。

### 修改

- `ensureCookieJar` 默认 `maxAgeMs = 0` 改为「本次调用就重新导出」，导出失败仍回退旧缓存。
  整轮抓取（fetch-streams / fetch-danmaku / fetch-live-chat / daily-update /
  backfill-owner-chats）只导出一次，之后共用同一个 jar。
- 移除各脚本的 `--refresh-cookies`：默认行为已经是刷新，保留只会误导。
- `ytdlpCookieArgs` 增加 `source === 'none'` 分支：`--no-cookies` 现在真的匿名，
  不会因为「没有 jar 就回退浏览器」把登录态又带回来。
- 文档同步：`scripts/README.md` 的 cookie 缓存一节、`docs/data/data-model.md`、
  `CHANGELOG.md` 与 [backlog B22](../planning/backlog.md)；
  复盘见 [postmortem 003](../postmortem/003-stale-yt-cookies-cache.md)。
- 在 `scripts/README.md` 记下本地需要 deno（yt-dlp 解 YouTube JS challenge），
  以及 SABR-only 警告不影响本仓库的抓取范围。

### 验证

- `bun x vitest run scripts/lib/yt-cookies.test.ts`：9 个用例通过，新增
  `--no-cookies` 不把浏览器 cookie 带回 yt-dlp。
- 走真实 `resolveCookies({ browser: 'firefox', appRoot })`：
  `重新导出：从 firefox 导出到 ~/yt-cookies.txt（57 条，youtube.com 24 条）`，
  随后 `yt-dlp -J --cookies ~/yt-cookies.txt …` 退出码 0。
- 环境：yt-dlp 2026.10.26、deno 2.9.8。

## 环境变量：`LOCAL=0` 时要回到 `.env`

### 现象

`LOCAL=0` 跑 `publish-transcripts` 时日志显示「线上模式 · 数据库 localhost:5432/ymmt_dev」，
对象传到了 R2，`transcripts` 元数据却写进本地库。

### 原因

- `loadEnvFiles()` 原来按 `.env` → `.dev.vars` → `.env.local` 覆盖，但没有「本地文件只在
  `LOCAL=1` 时生效」的概念，`.env.local` 里的本机 `DATABASE_URL` 一直压着 `.env` 的 Neon。
- 更隐蔽的一层：Bun 启动时先把 `.env*` 灌进 `process.env`，且同名键先读到的赢（`.env` 盖住
  `.env.local`），原来的「变量已存在就跳过」写法让文件优先级完全失效，真实生效的其实是 Bun 的加载顺序。

### 操作

- `scripts/lib/env.ts`：
  - 文件里出现过的键一律以 `loadEnvFiles()` 的合并结果为准，不再被 Bun 预注入的值挡住；
    `LOCAL` 是例外——运行环境设了就优先（命令行 / `bun run dev --local`）。
  - `DATABASE_URL` / `NEON_HTTP_ENDPOINT` 只在 `LOCAL=1`（或 `devServer`）时采用 `.env.local` /
    `.dev.vars` 的本机值；`LOCAL=0` 只认 `.env`。
- `scripts/dev.ts` 传 `{ devServer: true }`：开发服务器始终准备并连本机库，`LOCAL` 只管对象存储与媒体地址。
- `scripts/lib/env.test.ts` 补 6 个用例（线上只认 `.env`、`LOCAL=1` 用本机、运行环境压过文件、
  dev 服务器固定本机、其余键仍按顺序覆盖、Bun 预注入不挡文件）。
- 文档：`docs/engineering/local-database.md`「与线上环境的关系」、`scripts/README.md` 环境提示小节。

### 验证

- `bun scripts/publish-transcripts.ts --no-upload` → `线上模式 · 数据库 ep-lively-sun-…/neondb`；
  `LOCAL=1` 同命令 → `本地模式 · 数据库 localhost:5432/ymmt_dev`。
- `loadEnvFiles({ devServer: true })` → `线上模式 · 数据库 localhost:5432/ymmt_dev · 对象存储 R2`（与改动前一致）。
- `bun run test`：355 通过；`bun run lint`：0 warnings / 0 errors。
- `bun run typecheck` 未通过：本机 TypeScript 7 与 `astro check` 不兼容（`astro check does not currently support TypeScript 7.0`），与本次改动无关。
