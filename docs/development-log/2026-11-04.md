## 阶段 5：数据链路切换、客户端媒体清理与部署配置

**做了什么**

- **每日任务改为数据库差集**：`scripts/daily-update.ts` 不再读 R2 / 本地 manifest，改为查 `streams` 与 `dataset_insights.generated_at`；本地 pack 比数据库新时补一次 ingest。抓取后的顺序固定为：逐字稿 → `ingest-db` → `publish-data --assets-only` → `purge-cache`。
- **资产发布拆分**：`publish-data.ts` 新增 `--assets-only`，只上传 thumbs / emoji / archive；原始 pack 的 key 从 `<id>/<videoId>.datapack.json` 改为 `archive/<id>/<videoId>.datapack.json`，不再写 manifest / insights / group-* / index。新增 `publish:assets` 脚本。
- **缓存失效**：新增 `scripts/lib/purge.ts` 与 `scripts/purge-cache.ts`，支持 `--tags` / `--dataset` / `--video`；每日任务与 `fetch-streams --publish` 在数据库提交后调用。新增 `db-latest-video.ts`，数据工作流的 YouTube 探针改查数据库。
- **客户端媒体统一**：`src/lib/media.ts` 改为封面 / 表情的统一入口，使用 `PUBLIC_R2_BASE`；删除 `src/lib/data.ts` 与 `data.test.ts`，更新 `StreamCover` / `EmojiImage` / `useEmojiIndex`。
- **逐字稿正文**：新增 `src/pages/api/transcripts/[datasetId]/[videoId].ts`，从 R2 binding 读取正文；`useTranscript` 改为请求同源 API，开发环境回退本地 Markdown 快照。单场页的逐字稿可用性改为完全由数据库传入，删除客户端索引请求。
- **数据工作流**：`data.yml` 增加 `DATABASE_URL` / `SITE_URL` / `PURGE_TOKEN`，移除 `VITE_DATAPACK_BASE` 检查；探针改为 `db-latest-video.ts`。
- **部署**：新增 `.github/workflows/deploy.yml`（手动触发）；`cf:deploy` 改为 `wrangler deploy --config dist/server/wrangler.json`。根目录 `wrangler.jsonc` 只是 adapter 的源配置。
- **清理**：删除 `public/data/`、`.gitignore` 里的旧条目；`validate-data.mjs` 改为校验本地 pack 与 archive；`restore-datapacks` 从 `archive/` 读取并兼容旧公开路径。
- **文档**：重写 `architecture.md`、`deployment.md`、`performance.md`、`release-checklist.md`；同步 `AGENTS.md`、`README.md`、`CONTRIBUTING.md`、`data-model.md`、`adding-data.md`、`data-progress.md`、`scripts/README.md`、需求与迁移验收清单。

**为什么**

- 迁移计划阶段 5 要求「数据库是唯一读源」；继续读 manifest 会让新场次依赖 R2 JSON，和 SSR 查库模型冲突。
- `VITE_DATAPACK_BASE` 已从部署链路移除，但客户端封面 / 表情 / 逐字稿还在读它；不配置时封面会落到已删除的 `/data/`，线上会破图。
- 逐字稿正文放在公开 R2 域名下与方案不一致；改为同源 API 后，桶的公开域名只用于封面与表情。
- 直接 `wrangler deploy` 会把 `dist/server` 与 `.dev.vars` 当静态资源上传；必须使用 adapter 生成的 `dist/server/wrangler.json`。

## 开播前 / 直播中弹幕采集（InnerTube）

**做了什么**

- 新增 `scripts/fetch-live-chat.ts`、`scripts/lib/innertube-live.ts`、`scripts/lib/live-chat-events.ts`：watch 页（浏览器 UA + `hl=en`）→ reload / timed / invalidation continuation → `youtubei/v1/live_chat/get_live_chat`，逐页落 `danmaku/danmaku_live_<videoId>.jsonl` 与 `events_<videoId>.jsonl`。
- 消息口径与回放一致：text / SC / 贴纸 / 会员 / 赠送会员 / 领取赠礼、徽章、authorId、频道表情、主播发言；记录追加 `rendererId`。
- 非消息事件全覆盖：置顶、投票（含票数快照）、Q&A、商品、系统提示、慢速 / 模式变更、删除 / 按作者删除、替换；ticker 是消息副本，忽略并计入 `skipped`。主播操作标 `owner: true`，删除事件对回被删消息的作者与是否主播。
- `scripts/lib/danmaku-merge.ts`：回放与实时采集按 `rendererId`（缺失时 `timestampUs + 作者 + kind + text`）去重合并；`fetch-streams` / `fetch-danmaku` 抓到回放后自动合并。
- `stream-datapack`：`chat.events` 写结构化事件；owner 事件并入 `chat.ownerChats`（`kind: "event"`），供 `?view=words` 直接展示；投票更新合并为最后一次快照。
- 类型与文档：`src/types/datapack.ts` 增加 `ChatEvent` / `OwnerChat.kind = "event"`；`docs/data/data-model.md` 增加 §8 与 `events` 字段。
- 数据库：`stream_details` 增加 `events` jsonb 列（`drizzle/0001_add_stream_events.sql`）；`ingest-db` 写入、`packs.ts` 读回，`ownerMessages` 改为只数消息、不数事件。

**为什么**

- yt-dlp 的 `live_chat` 字幕只在直播结束后存在，等待室与直播中的弹幕拿不到；但 `?view=words` 需要完整词频、主播发言与付费事件。
- 原有 `toRecord` 只覆盖六种消息，置顶 / 投票 / 系统提示会静默丢失；事件单独落 sidecar，既不污染词频，又保留原始 renderer 供以后重解析。

**验证**

- `bun run check`：`astro check` 0 error、226 个测试通过、oxlint 0 warning。
- 等待室实测 `fmjJNbzcr3g`：一次 reload 拉到 73 条消息、4 个事件（投票 / 置顶 / 删除 / 系统），16 笔 SC；`stream-datapack --out` 生成 `chat.events` 4 条、`ownerChats` 2 条。
- 单元测试覆盖 continuation 优先级、等待室 / 已结束 / 受限判定、六种消息、置顶 / 投票 / 删除 / ticker、合并去重。
