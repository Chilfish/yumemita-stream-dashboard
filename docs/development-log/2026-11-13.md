# 2026-11-13

## VSTATS 缺条目按预期处理，用抓取快照兜底

问题：`daily-update` 每天把 400 多场标成「已放弃（缺 VSTATS 已超过 14 天）」，占了运行摘要的大半。
核对这些场次后发现是预期行为，不是抓取坏了：

- 线上 `arale` 公开场次 401 场缺 VSTATS，且全部集中在 2026-08 之前；站点对该企划的收录从 2026-08 中旬开始。
- 这 401 场都有 yt-dlp 抓取快照（`snapshotViews` / `snapshotLikes`），页面本来就按 `vstatsViews ?? snapshotViews` 读。
- 另外 4 场是真正的缺弹幕，与 VSTATS 无关。

原逻辑有两个副作用：

1. `fetch-streams` 把 VSTATS 的网络 / 站点异常计入 `failures`，一场 VSTATS 失败会挡住整场入库与发布。
2. `update-plan` 只在 `vstatsGapDays` 内重试，超窗后一律列为 `expiredIds`，没有考虑「已用快照兜底」这种正常终态。

### 改动

- `scripts/fetch-streams.ts`：VSTATS 只按内容特征识别（必须含「平均視聴者数」），错误页 / bot 检查页不再写成快照；抓取异常只记日志，不再计入失败项。
- `scripts/lib/update-plan.ts`：新增 `fallbackIds`。超过 14 天窗口仍缺 VSTATS 时，有 `snapshotViews` / `snapshotLikes` 的归入兜底，连快照都没有才进 `expiredIds`。
- `scripts/daily-update.ts`：查询带上快照列；摘要新增一行「兜底 N 场」。
- 文档：`scripts/README.md`、[data-progress.md](../data/data-progress.md) 同步口径。
