# 2026-11-13

## VSTATS 缺条目按预期处理，页面用抓取快照兜底

问题：每日任务把 400 多场标成「已放弃（缺 VSTATS 已超过 14 天）」，占了运行摘要的大半。
核对这些场次后发现是预期行为，不是抓取坏了：

- 线上 `arale` 公开场次 401 场缺 VSTATS，且全部集中在 2026-08 之前；站点对该企划的收录从 2026-08 中旬开始。
- 这 401 场都有 yt-dlp 抓取快照（`snapshotViews` / `snapshotLikes`），页面本来就按 `vstatsViews ?? snapshotViews` 读。
- 另外 4 场是真正的缺弹幕，与 VSTATS 无关。

### 改动

- `scripts/commands/data/fetch.ts`（`data fetch`）：VSTATS 页面按 `scripts/lib/vstats.ts` 的解析结果识别——
  字节数够 `VSTATS_MIN_HTML_BYTES` 且能解出播放 / 平均同接才算单场页。站点错误页 / bot 检查页
  同样可能超过 1KB，原先只按长度判断会把垃圾写进快照。
- 同文件：VSTATS 抓取异常（超时、5xx）只写日志，不再计入 `failures`。VSTATS 是可选数据源，
  它失败不该挡住整场的入库与发布；播放 / 点赞有抓取快照兜底。
- 缺 VSTATS 的重试与终态不在 `scripts/lib/update-plan.ts` 里处理：`data update` 每轮固定跑一次
  `data vstats`（`scripts/commands/data/vstats.ts`，候选为 manifest 里 `vstatsViews` 为空且公开的场次，
  按随机配额轮转），未收录只记「未收录」，不记失败、也不进「已放弃」。见 [2026-11-14](./2026-11-14.md)。
