# 用户故事（User Stories）

> 按 Epic 分组。状态与验收标准需与 [requirements-spec.md](./requirements-spec.md) 的 FR 对齐。

## Epic 1：浏览数据

### US-1：一进站就知道最近谁播了

> 作为**访客**，我想要**在组首页看到全组最新动态**，以便**决定先看谁的哪一场**。

- **状态**：✅ 已完成（`FR-HOME-001`）
- **验收标准**：
  - [x] `/` 展示近 7 天 / 本月脉冲、全组最新一场、最近更新与成员入口
  - [x] 单个成员加载失败时，其余成员仍正常显示
  - [x] 成员入口带头像、名字与最新场次信息

### US-2：快速判断某位成员近况

> 作为**观众**，我想要**在成员首页看到规模、最近一场与本月变化**，以便**判断她最近播得怎么样**。

- **状态**：✅ 已完成（`FR-MEMBER-001`）
- **验收标准**：
  - [x] `/:datasetId` 展示场次、弹幕、SC、时长等规模指标
  - [x] 最近一场、本月变化、更新日历可见
  - [x] `vstats` 缺失的场次显示「—」，不画 0

### US-3：浏览与筛选场次

> 作为**观众**，我想要**搜索、按类型筛选、排序并导出场次**，以便**找到想看的那一场**。

- **状态**：✅ 已完成（`FR-STREAM-001`）
- **验收标准**：
  - [x] `q` / `type` / `sort` / `dir` / `vstats` 写入 URL，可分享
  - [x] 刷新、前进后退保持筛选状态
  - [x] 空结果有说明与清除筛选入口
  - [x] 可导出 CSV

### US-4：下钻单场详情

> 作为**观众**，我想要**查看一场直播的指标、时间轴、弹幕、付费与评论**，以便**理解这场发生了什么**。

- **状态**：✅ 已完成（`FR-STREAM-002`）
- **验收标准**：
  - [x] 概览、时间轴、弹幕与词、付费、评论可切换
  - [x] `?view=` 可直接分享到某个分段
  - [x] 图表空数据有说明，不渲染误导性 0
  - [x] 有逐字稿时出现对应分段

### US-5：看长期趋势

> 作为**观众 / 维护者**，我想要**按月份和内容类型看趋势**，以便**比较不同时期的场次与互动**。

- **状态**：✅ 已完成（`FR-TREND-001`）
- **验收标准**：
  - [x] 月度趋势与月度明细可排序
  - [x] 内容类型对比可用
  - [x] 典型节奏曲线与全期榜单可见

### US-6：按画面回看

> 作为**观众**，我想要**按月份浏览封面墙**，以便**从画面而不是表格找到一场直播**。

- **状态**：✅ 已完成（`FR-GALLERY-001`、`FR-GALLERY-002`）
- **验收标准**：
  - [x] 成员相册按 JST 自然月分组
  - [x] 全组相册支持 `member` / `type` 筛选并写进 URL
  - [x] 图片懒加载，缺图走成员色兜底
  - [x] 390 / 320px 无横向滚动

### US-7：对比场次

> 作为**分析者**，我想要**选择最多 4 场叠加逐分钟曲线**，以便**比较节奏与互动差异**。

- **状态**：✅ 已完成同成员对比（`FR-COMPARE-001`）；跨成员对比待做（`FR-COMPARE-002`）
- **验收标准**：
  - [x] `?ids=a,b,c` 可分享
  - [x] 逐分钟曲线叠加，指标横表可读
  - [x] 超过 4 场有明确限制
  - [ ] 跨成员、同时间段 / 同内容类型对比

## Epic 2：回看内容

### US-8：阅读逐字稿

> 作为**观众**，我想要**在单场页读到整理好的逐字稿并跳到视频时间点**，以便**快速回看关键内容**。

- **状态**：✅ 已完成（`FR-TRANSCRIPT-001`）
- **验收标准**：
  - [x] 逐字稿源文件进 git，正文发布到 R2
  - [x] 单场页只在有稿时显示逐字稿分段
  - [x] 索引页按月份列出稿件
  - [x] 行首时间码跳转 YouTube 对应位置
  - [x] 320px 下正文不横向溢出

## Epic 3：维护数据

### US-9：增加一场直播或一位成员

> 作为**维护者**，我想要**只改数据配置和 pack 就能增加场次或成员**，以便**不改组件也能扩展**。

- **状态**：✅ 已完成（`FR-DATA-001`、`FR-DATA-002`）
- **验收标准**：
  - [x] 加场次只需放 pack 并 `publish:data`
  - [x] 加成员只需 `data-sources.json` 与 pack 目录
  - [x] manifest / insights 由脚本派生，不手改
  - [x] `validate:data` 通过

### US-10：每天自动补新场次

> 作为**维护者**，我想要**每天自动做频道差集、只抓变化的场次并发布**，以便**安静日不产生额外成本**。

- **状态**：✅ 已完成抓取与发布；静态 SEO 刷新仍需完整构建（`FR-DATA-003`、`FR-DATA-004`、`FR-OPS-001`）
- **验收标准**：
  - [x] 先拉频道列表，与已知场次求差集
  - [x] 无变化时不恢复 pack、不发布
  - [x] 失败开 issue，不静默断更
  - [x] `workflow_dispatch` 可手动触发并附加 `--force`
  - [ ] 数据更新后自动刷新 sitemap 与静态 head

## Epic 4：工程与迁移

### US-11：提交前能发现回归

> 作为**开发者**，我想要**在提交前跑统一的检查**，以便**不把类型、测试或 SEO 问题带到线上**。

- **状态**：✅ 已完成（`FR-BUILD-001`）
- **验收标准**：
  - [x] `bun run check` 覆盖 typecheck、test、lint
  - [x] `bun run build` 能完成数据同步、类型检查与构建
  - [x] `bun run check`、`bun run build`、`bun run db:verify` 可独立运行

### US-12：让 Agent 读取单场数据

> 作为**使用 Agent 的分析者**，我想要**通过一个 `.md` 地址拿到单场结构化摘要和逐字稿**，以便**不解析 HTML 就能分析**。

- **状态**：📋 规划中（`FR-AGENT-001`，见 [astro-ssr-migration.md](../planning/astro-ssr-migration.md)）
- **验收标准**：
  - [ ] `/{datasetId}/stream/{videoId}.md` 返回 `text/markdown`
  - [ ] frontmatter 含标题、日期、成员、canonical
  - [ ] 包含概览、部分指标与原始逐字稿
  - [ ] 未知 id 返回 404，不进 sitemap

### US-13：迁移到 Astro + 数据库

> 作为**维护者**，我想要**把数据页改成请求期 SSR、把 datapack 投影到 PostgreSQL**，以便**新场次不触发前端构建，并支持检索与聚合**。

- **状态**：📋 规划中（`FR-ARCH-001`，见 [astro-ssr-migration.md](../planning/astro-ssr-migration.md)）
- **验收标准**：
  - [ ] 数据库行数与 manifest 对账通过
  - [ ] 单场页、成员页、组首页由数据库查询渲染
  - [ ] `.md` 路由、sitemap、缓存失效可用
  - [ ] 旧 URL、canonical、OG 保持
  - [ ] 新场次入库后不触发前端构建即可访问
