# 示例

## 1. 官方一天的预告

用户说：「按这个预告加：11/8 晚上ののか、11/9 早上りつ和みやこ」

1. 换算日期：`2026-11-08`、`2026-11-09`。
2. 三条 POST，均不带 `title`。
3. GET `from=2026-11-08&to=2026-11-09` 验证。
4. 回复表格，标题列写「待定」。

## 2. 只知道某天有直播

用户说：「10 号あられ有直播，时间不知道」

缺少时段不能直接写，先问「早上、中午还是晚上？」再提交。用户坚持不知道时不写，
说明日历需要时段才能定位。

## 3. 改期

用户说：「把 11/8 晚上ののか改到 11/9 晚上」

1. GET 找到 `eventKey`（`manual:2026-11-08-late`）。
2. PATCH 该行，传 `date: "2026-11-09"`、`slot: "late"`；返回 `409` 说明目标时段被占。
3. 再 GET 确认。

## 4. 预告只给频道首页

用户说：「按这条推文排今天的，链接点进去是各成员频道」

1. 频道链接只说明成员，不能反推「最新 upcoming 就是他这一场」。
2. 先按推文 `HH:00` + `slot` 写入，标题留空。
3. 再抓频道 `/streams`：谁 `is_live` 就用那条的标题与 id 回填；仍 `is_upcoming` 的一律当未开播，不挂链接。

## 5. 第三方官方账号的联动场

用户说：「这档节目的第一期 11/25 20:00，りつ和ゆの出演」，附 `x.com` 推文和 YouTube 链接。

1. 推文里的 `t.co` 解析为 `youtube.com/live/<id>`，yt-dlp 确认 `is_upcoming`、`public`，
   `release_timestamp` 为 `2026-11-25T20:00:00+09:00`，与推文一致，不是占位值。
2. 归属不是成员频道：第三方账号归聚合官方账号 `other`。
3. 一条 POST：

```bash
-d '{"datasetId":"other","title":"パルカNEWS｜パルワールド オフィシャルカードゲーム","scheduledAt":"2026-11-25T20:00:00+09:00","kind":"event","url":"https://www.youtube.com/live/zdFXJG5tRWc","participants":["ritsu","yuno"],"source":"manual"}'
```

4. GET 验证 `state=upcoming`、`timeTentative=false`、`date=2026-11-25`、`slot=late`。
5. 每周固定节目只录已公布的场次，后续各周等新预告再加。
